## 自动化覆盖

### 尺寸和方向

- `4032×3024 → 1280×960`；
- `3024×4032 → 960×1280`；
- `800×600` 不放大；
- 奇数尺寸保持比例，舍入误差不超过一个像素；
- EXIF 0°、90°、180°、270° 均旋正到正确像素尺寸；
- 输出文件可解码，最终 EXIF 方向为正常。

### 拍摄配置和任务

- Preview、ImageCapture 和 postview 的 4:3 选择策略；
- 约 5MP 目标尺寸及“优先较低”的回退规则；
- 三个未落盘任务的队列上限；
- 回调乱序不会让任务状态倒退；
- 单张失败不破坏其他任务；
- 点击完成后等待所有已接受任务终结。

### Compose 状态

- 权限说明、请求中、拒绝、相机启动、就绪、无相机和错误重试；
- 拍摄过程中 Preview 与快门继续显示；
- 队列满时只禁用快门；
- 对焦框、缩略图、单张失败和结果页；
- 竖屏 `3:4`、横屏 `4:3` 取景比例；
- 取景框与控制区不重叠。

## 通用真机前置条件

1. 设备具有后置摄像头并已开启开发者选项和 USB 调试；
2. `adb devices -l` 显示状态为 `device`；
3. 设备保持解锁，系统相机未占用摄像头；
4. 分别准备含小字、表格、公式和低对比度内容的文档样本；
5. 在普通室内光下预热相机后再记录性能；
6. 测试期间保持闪光灯关闭，并记录系统自动旋转是否开启。

## 真机功能验收

### 权限与恢复

- 宿主 App 启动时不提前请求相机权限；
- 首次进入相机功能时显示用途说明并请求权限；
- 拒绝后页面可重试，也可引导至系统设置；
- 从系统设置授权并返回后能够重新绑定相机；
- 切入后台再返回时不会重复归一化已经完成的图片。

### 取景、对焦和方向

- 竖屏取景框为 `3:4`，控制区位于下方；
- 横屏取景框为 `4:3`，控制区位于右侧；
- Preview 内容完整，没有为了铺满屏幕而裁切；
- 点击近处和远处文字时，对焦框位置与触点一致；
- 对焦失败或仍在进行时可以继续拍照；
- 竖屏、左右横屏和反向竖屏照片方向正确；
- 系统旋转锁定开启和关闭时分别验证一次。

### 连续拍摄与文件

- 一秒内连续点击三次，三个请求都被接受；
- 第四个未落盘请求被临时限制，不覆盖已有文件；
- Preview 不因保存或归一化而消失；
- 每个 `captureId` 目录同时存在 `original.jpg` 和 `normalized_1280.jpg`；
- 两个文件均可解码，原图保持设备实际选择的 4:3 分辨率；
- 横向 OCR 图为 `1280×960`，纵向 OCR 图为 `960×1280`；
- 较小图片不放大，内容无裁切、拉伸或补边；
- 单张失败可以重试或移除，不影响其他照片。

## 性能验收

建议在相同光照、构图和预热条件下连续拍摄至少 20 张：

| 指标 | 当前目标 |
|---|---:|
| 点击后的视觉/触觉反馈 | 不超过 100 ms |
| 点击至 JPEG 保存中位数 | 小于 700 ms |
| 点击至 JPEG 保存 P95 | 小于 1000 ms |
| 一秒内连续三次拍摄 | 全部接受、无丢图、无覆盖 |
| 归一化 | 后台串行完成，不阻塞下一次拍摄 |

## OCR 输入对照

使用同一批含小字的页面比较最长边 1024 和 1280 两档派生图：

- 固定服务端模型、prompt、`max_pixels` 和生成参数；
- 记录 JPEG 体积、上传耗时、processor 的实际网格和 image tokens；
- 对比漏字、错字、表格结构、公式和阅读顺序；
- 同时记录首 token、总推理耗时和峰值显存；
- 根据质量与成本决定正式上传规格，不只比较肉眼清晰度。

当前 Android 默认采用 1280 像素长边；PaddleOCR 的 1280 image-token 档仍由服务端 `max_pixels` 控制。

当前 1024/1280 输入对照已经完成，正式客户端规格继续采用 1280 像素长边。本文只记录验收结论，不保存单次测试的原始性能数据。

## 已知限制

- 单台连接设备通过不能代表所有 Android 厂商、API 版本和屏幕比例；
- 自动化布局测试不能替代真实 Preview 构图检查；
- 当前没有自动触发真实快门，避免测试过程无意采集环境画面；
- 当前任务仅保存在进程内，进程死亡恢复不属于本轮通过条件；
- 文档检测、透视校正、OCR 上传和端到端结果不属于相机探针验收范围。
