# Android App 产品与架构草案

> 状态：产品方向草案
> 基线日期：2026-09-03

## 文档目的

本文档记录 Android App 的产品定位、功能边界和初始工程组织。它不冻结聊天后端、账号体系、服务端 API 或 UI 视觉稿；这些内容需要在后续原型中继续验证。

## 产品定位

Android App 的主体是一个类似 ChatGPT 或豆包的对话式助手。用户以会话作为主要工作入口，通过文字、图片、文件或工具完成任务。

拍照/视频转文档不是整个 App 的首页主流程，而是工具系统中的一个独立功能。本文暂称该工具为 **Capture2Doc**：它负责采集文档页面、确认页面顺序、提交本地解析任务，并把生成的文档作为结果返回宿主 App。

宿主 App 的最终产品名、助手能力范围及 Capture2Doc 是否继续作为仓库名，尚待确定。

## 产品结构

```text
宿主 App
├── 对话
│   ├── 会话列表
│   ├── 消息流
│   └── 输入区
├── 工具入口
│   └── Capture2Doc
│       ├── 拍照或视频取帧
│       ├── 页面确认与排序
│       ├── 上传、finalize 与任务进度
│       └── 文档预览与导出
├── 生成物
│   └── Lark 文档、Markdown 或思源 `.sy`
└── 设置
    ├── 助手与模型服务
    └── Capture2Doc 本地服务
```

用户可以从对话输入区的附件或工具入口启动 Capture2Doc。工具完成后，应返回一个或多个文档生成物；宿主 App 再决定把结果插入当前会话、打开预览或保存到生成物列表。

## 功能边界

### 宿主 App

- 管理会话、消息、输入区和全局导航；
- 展示工具入口并管理工具启动与返回；
- 展示文件、图片和其他生成物；
- 管理聊天服务及工具服务的独立配置；
- 提供全局主题、权限解释、错误展示和设置入口。

### Capture2Doc 工具

- 管理一次文档采集会话；
- 支持拍照，以及后续的视频关键帧提取；
- 完成页面检测、裁边、旋转、透视矫正、质量判断和去重；
- 允许用户删除、重拍和调整页面顺序；
- 可靠上传页面并显式触发 `finalize`；
- 展示服务端处理状态并接收最终文档生成物。

### Capture2Doc Server

- 接收工具提交的页面和采集元数据；
- 运行本地页面解析、多页组装和 C2D-XML 校验；
- 从通过校验的 C2D-XML 生成目标文档；
- 不承担宿主 App 的聊天会话管理，除非后续单独设计统一服务协议。

聊天模型服务和 Capture2Doc 本地服务是两个独立边界。当前不假设它们使用相同模型、进程、鉴权或部署设备。

## Android 架构基线

初始工程采用：

- Kotlin、Jetpack Compose 和 Material 3；
- 单 Activity 作为宿主；
- 状态向下、事件向上的单向数据流；
- Screen-level ViewModel 对外暴露不可变 UI State；
- Repository 作为 UI 与本地/远端数据源之间的边界；
- 普通前台异步任务使用 Kotlin Coroutines；
- 需要跨进程恢复的上传和同步任务使用 WorkManager；
- 扫描会话、页面元数据和上传状态最终以本地持久化数据为事实来源；
- 图片文件与结构化元数据分开保存，不把大图放进 ViewModel 或导航参数。

当前只为独立拍照探针接入 CameraX 和 screen-level ViewModel。正式导航、数据库、依赖注入和网络库尚未接入；这些能力应在对应功能进入当前里程碑时再引入，不为原型预装完整技术栈。

## 初始代码边界

第一阶段保持单个 `:app` Gradle 模块，但按功能边界组织 package：

```text
app
├── feature/chat
├── feature/tools
├── feature/capture2doc
├── core/model
├── core/ui
├── data/conversation
└── data/capture2doc
```

当聊天、扫描、图像处理和可靠上传的接口稳定后，再根据高内聚、低耦合原则拆分 Gradle 模块。当前不复制大型项目的多模块数量，也不为每个操作机械建立 Use Case 或接口。

## 工具集成原则

宿主 App 与工具之间需要一个稳定但足够小的概念契约：

- 启动上下文：工具从哪个会话或入口打开；
- 生命周期：未开始、执行中、需要用户处理、完成、失败或取消；
- 结果：工具生成的文件及其类型、显示名称和本地引用；
- 返回动作：插入当前会话、打开预览或保存；
- 恢复：App 被系统回收后仍能从持久化状态恢复任务。

该契约不直接暴露 CameraX、Room、HTTP DTO 或具体模型类型。确切 Kotlin 数据结构应等第一个工具闭环明确后再冻结。

- 浅色、深色和 Android 动态配色；
- 临时的扫描功能入口和 CameraX 拍照探针；
- 摄像头运行时权限、后置摄像头预览和高质量 JPEG 拍摄；
- 原图保留、EXIF 方向校正和最长边 1280 像素的 OCR 派生图；
- 拍照结果预览、尺寸/文件大小/耗时展示和独立 UI State；
- Gradle Wrapper、Debug APK 构建和 Android Lint；
- Debug APK 已安装到连接的 Android 真机。

尚未完成：

- 对话首页、消息流和输入区；
- 工具注册表及工具入口；
- 正式页面导航、跨进程状态恢复、Repository 和持久化元数据层；
- 文档检测、透视校正、质量判断、网络及后台上传；
- 正式产品导航和端到端 Compose 测试。

当前扫描首页和相机探针只是工程及硬件能力验证页面，不代表最终产品首页。后续应把它们移动到 Capture2Doc 工具边界内。

## 前置技术探针：CameraX 拍照

在对话式应用外壳之前先完成一个边界明确的 CameraX 探针，通过 Android 真机验证权限、4:3 取景、拍照、方向处理和文件尺寸。探针保留原始 JPEG，并生成不裁剪、不拉伸、最长边不超过 1280 像素的 JPEG OCR 派生图。该像素规格独立于 PaddleOCR 的 image-token 上限，模型侧仍由 processor 的 `max_pixels` 控制最终输入预算。

该探针不冻结最终导航、扫描 UI、页面模型或工具结果契约。实现说明见 [Android 相机架构与状态管理](android_camera_architecture.md) 和 [Android 相机拍摄与图像处理](android_camera_capture.md)，验收方法见 [Android 相机测试与验收](android_camera_testing.md)。

## 下一里程碑：对话式应用外壳

下一里程碑先验证产品结构，不连接真实聊天模型或文档服务：

1. 建立对话式首页，包括空消息区、输入框和发送入口；
2. 使用本地 Mock 消息验证消息展示和基本状态；
3. 增加工具入口，并展示 Capture2Doc 工具卡片；
4. 从工具卡片进入现有扫描/相机探针，并能返回原会话；
5. 保持旋转、后台切换和 Activity 重建后的基础界面状态；
6. 在连接的 Android 真机上执行核心导航与 Compose 冒烟测试。

该里程碑不包含真实模型调用、账号登录、聊天云同步、文档上传，也不继续扩展 CameraX 探针为正式扫描流程。

## 待决策事项

1. 宿主 App 和仓库的最终命名；
2. 聊天能力连接本地服务、云服务还是可插拔的多 Provider；
3. 首版是否需要账号、跨设备同步和远端会话历史；
4. 工具生成物是否必须回到当前对话，还是同时进入独立文档空间；
5. 主导航采用单一对话入口，还是包含独立的会话、工具和生成物页面；
6. 聊天消息、工具调用与生成物的本地持久化模型；
7. Capture2Doc 页面身份、顺序调整和 `finalize` 的最终 API 契约。
